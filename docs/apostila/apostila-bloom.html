Capítulo 1

O que é a Bloom

A Bloom é uma plataforma que conecta mulheres que trabalham ou querem trabalhar com tecnologia a empresas que contratam, e que funciona também como uma rede social profissional: publicações, comunidades por tema, conexões e mensagens.

Quem usa

QuemO que fazOnde entra
VisitanteConhece a plataforma, vê o diretório e o perfil público das empresas e as vagas abertas./, /empresas
CandidataMonta o perfil, publica, participa de comunidades, conversa, salva vagas e se candidata./login → /candidata/feed
EmpresaPublica vagas, acompanha candidaturas por etapa, busca talentos, conversa com candidatas e verifica o vínculo de quem administra a conta./empresa/login → /empresa/feed
Equipe BloomModera conteúdo, trata denúncias, suspende contas, envia comunicados e exporta relatórios./admin
Princípio

Nada de dados inventados nas telas: tudo o que aparece vem do banco. Quando não há dados, a tela mostra um estado vazio com um convite (por exemplo, "Ainda não há empresas na Bloom").

Revisão

Quais são os quatro tipos de pessoa que usam a Bloom?

Visitante (sem conta), candidata, empresa e equipe da Bloom (administração).

O que diferencia a Bloom de um simples site de vagas?

A parte de rede social: feed, comunidades temáticas, seguir pessoas e mensagens entre candidatas, além das vagas e candidaturas.

Serviços externos e o que acontece sem eles

  • BrasilAPI (CNPJ) — gratuita e sem chave; o cadastro de empresa depende dela.
  • Serpro (CPF) — paga; sem as chaves, o CPF fica "não verificado" e o cadastro segue.
  • Resend (e-mail) — sem a chave, em desenvolvimento o conteúdo do e-mail aparece no terminal da API.
  • Mercado Pago — sem o token, as telas mostram os planos mas nada é cobrado.

Revisão

Por que a senha é guardada com bcrypt e não em texto?

Porque bcrypt gera um hash lento e com "sal": mesmo quem lê o banco não descobre a senha, e testar senhas por força bruta fica caro.

O que acontece no cadastro se o Serpro não estiver configurado?

A conta é criada normalmente, com o CPF marcado como "não verificado".

Capítulo 3

Arquitetura MVC

Front e API vivem no mesmo projeto: uma pasta src/, um package.json. O padrão é MVC: Model (tabelas), View (o front em React) e Controller (regras de cada recurso).

src/ ├── models/ M — tabelas do banco (Sequelize) ├── views/ V — o front em React (pages, components, services, hooks) ├── controllers/ C — recebem a requisição, usam os models e respondem ├── routes/ ligam cada URL /api/... a uma função de controller ├── middlewares/ login obrigatório (exigirLogin, exigirAdmin) ├── services/ regras compartilhadas: notificações, e-mail, chat, representante… ├── utils/ JWT, imagens, limitador de tentativas, documentos, TOTP ├── database/ migrations SQL que rodam sozinhas ao iniciar a API ├── app.js configura o Express e monta as rotas └── server.js conecta no banco, aplica migrations e sobe a API

O caminho de uma requisição

Migrations

Mudanças no banco ficam em arquivos src/database/migrations/NNN_nome.sql. Ao iniciar, a API aplica os que ainda não rodaram e registra cada um na tabela SCHEMA_MIGRACAO. "Coluna já existe" conta como aplicado.

MigrationO que trouxe
001Área da empresa: etapas da candidatura, rascunho de vaga, campos do perfil da empresa
002Preferências de notificação e Bloom Premium (planos, assinaturas, pagamentos)
003Rede social: imagem e edição de publicações, ícones, mensagens entre candidatas
004Currículo da candidata e cópia anexada a cada candidatura
005Administração: administradores, registro de ações, suspensão de contas
006Denúncias
007Duas etapas para administradores, troca de senha obrigatória, comunicados
008Confirmação do e-mail da conta
009Capa e regras das comunidades; apagar mensagem entre candidatas
010Como e quando o representante da empresa foi verificado
011Chat: imagens nas mensagens, apagar mensagem com empresa, bloqueio entre candidatas

Revisão

Onde fica a regra "a empresa só vê candidaturas das próprias vagas"?

No controller (EmpresaController), que filtra pela conta do token. O front só mostra o que a API devolve.

O que acontece com uma migration nova quando a API reinicia?

Ela é aplicada uma única vez e registrada em SCHEMA_MIGRACAO; nas próximas vezes é pulada.

Capítulo 4

Como rodar o projeto

  1. Execute banco bloom.sql no MySQL (cria o banco BLOOM).
  2. Na raiz: npm install e copie .env.example para .env, preenchendo pelo menos DB_PASSWORD e JWT_SECRET.
  3. Em um terminal: npm run server (API em http://localhost:3001).
  4. Em outro: npm run dev (site em http://localhost:3006).

Comandos do package.json

npm run serverSobe a API (aplica as migrations antes)
npm run devSobe o front com recarga automática
npm run admin:criarCria o primeiro administrador (acesso total) pelo terminal
npm run admin:senhaRedefine a senha de um administrador e, se preciso, desliga as duas etapas
npm run demo:criar / demo:removerCria ou apaga as contas fictícias de demonstração
npm run lint / npm run buildConfere o código do front / gera a versão de produção

Cuidado

O .env nunca vai para o git. Trocar o JWT_SECRET desconecta todo mundo e invalida as chaves de duas etapas dos administradores.

Revisão

A tela de login diz "O servidor da Bloom não está respondendo". O que olhar?

O terminal do npm run server: normalmente o MySQL está desligado ou faltam DB_PASSWORD/JWT_SECRET no .env.

Como criar o primeiro administrador?

Com npm run admin:criar no terminal; não existe cadastro público de administrador.

Capítulo 5

Páginas públicas

Visíveis sem login: a home, o diretório de empresas e o perfil público de cada empresa. Os dados vêm de /api/publico, que tem limite de 60 pedidos por minuto por IP.

  • Home — apresenta a plataforma, as áreas de TI (cada uma abre as vagas da área) e a faixa "Conheça quem está contratando" com as empresas cadastradas.
  • /empresas — busca, filtro por área, "só com vagas abertas" e a seção "Contratando agora".
  • /empresas/:id — sobre, cultura, vagas abertas, site, LinkedIn e o selo Verificada quando o vínculo foi confirmado.
Privacidade

A API pública nunca devolve o e-mail de login, o CNPJ ou o nome de quem administra a conta da empresa. Empresas suspensas não aparecem.

Revisão

De onde vem a cidade de uma empresa que não preencheu a localização?

Dos dados públicos do CNPJ (município e UF) guardados no cadastro.

Por que a faixa de empresas da home pode não aparecer?

Porque ela some enquanto não houver nenhuma empresa cadastrada — nada de lista fixa.

Capítulo 6

Contas, cadastro e login

Cadastro da candidata

Nome, CPF (com dígitos validados), data de nascimento, e-mail e senha (mínimo de 8 caracteres). Com o Serpro configurado, nome e nascimento são conferidos com o CPF.

Cadastro da empresa

O CNPJ é consultado na BrasilAPI: a razão social, a situação cadastral e a cidade vêm de lá. Quem cadastra declara que pode representar a empresa.

Login e sessão

  • Login
  • →
  • Token JWT (8 h)
  • →
  • Enviado em cada pedido
  • →
  • Conferido no servidor

O token diz quem é a conta e o tipo (usuaria, empresa ou admin). O middleware exigirLogin confere a assinatura, a validade e se a conta não está suspensa.

Confirmação de e-mail

Ao se cadastrar ou trocar de e-mail, a conta recebe um link de uso único, válido por 24 horas. Enquanto não confirma, aparece o aviso "Confirme seu e-mail" no topo da área. Só o hash do token fica no banco.

Esqueci minha senha

O link de redefinição vale 30 minutos e uma única vez; a resposta é sempre a mesma, exista ou não a conta (assim ninguém descobre quais e-mails estão cadastrados).

Excluir a conta

A própria pessoa exclui a conta com a senha e a palavra EXCLUIR. Tudo o que é dela sai do banco numa transação (LGPD); fica só o registro financeiro de pagamentos.

Revisão

Por que o "esqueci minha senha" responde a mesma mensagem para qualquer e-mail?

Para não revelar quais e-mails têm conta na Bloom.

O que acontece com a verificação da empresa quando ela troca o e-mail da conta?

Se ela tinha sido verificada pelo domínio do e-mail, volta para pendente, porque o requisito mudou.

Capítulo 7

Área da candidata

Perfil

Foto (ou ícone), capa, cargo, localização, resumo, objetivo, competências técnicas e comportamentais, experiências, formações, cursos, links e preferências de vaga. "Complete seu perfil" mostra a porcentagem e o que falta.

Projetos e currículo

Projetos com descrição, tecnologias e links. O currículo (PDF, DOC ou DOCX até 5 MB, com o tipo conferido pelos primeiros bytes) pode ser anexado a cada candidatura — a empresa recebe uma cópia daquele momento.

Vagas e candidaturas

  • Recebida
  • →
  • Em análise
  • →
  • Em entrevista
  • →
  • Aprovada
  • ou Reprovada

A candidata filtra vagas, salva as favoritas, se candidata e acompanha cada etapa. Enquanto a candidatura está em Recebida, Em análise ou Em entrevista, ela pode retirá-la: o envio, a cópia do currículo e a conversa com a empresa são apagados e a empresa é avisada.

Configurações

E-mail (com a situação "Confirmado"), senha, notificações, privacidade do perfil (público ou oculto, mostrar experiências e contato), preferências e exclusão da conta.

Revisão

Por que a empresa recebe uma cópia do currículo e não o arquivo do perfil?

Para ver exatamente o que a candidata enviou naquela candidatura, mesmo que ela troque o currículo depois.

Dá para retirar uma candidatura já reprovada?

Não: só nas etapas Recebida, Em análise e Em entrevista.

Capítulo 8

Área da empresa

  • Perfil — logo/foto, capa, descrição, área de atuação, localização, site, LinkedIn e cultura.
  • Vagas — rascunho, aberta, pausada e encerrada. Vaga com candidaturas não volta para rascunho nem é excluída (é encerrada).
  • Candidaturas — por etapa; a candidata é notificada a cada mudança.
  • Banco de talentos e convites — respeita a privacidade de cada candidata; um convite por vaga.
  • Painel — números reais de vagas e candidaturas.

Verificação de quem representa a empresa

O CNPJ prova que a empresa existe, não que a pessoa fala por ela. A Bloom aceita dois caminhos:

  1. Automático, pelo domínio (Configurações → Verificação da empresa): CNPJ ATIVO, e-mail da conta confirmado, e-mail corporativo (não Gmail, Hotmail etc.) e no mesmo domínio do site informado no perfil.
  2. Pela equipe: a administração confere por um canal oficial e confirma no painel.

Empresas verificadas ganham o selo Verificada no diretório e nos perfis.

Revisão

Uma empresa com e-mail rh@gmail.com consegue a verificação automática?

Não: e-mails de provedores gratuitos não provam vínculo com a empresa. Ela pode pedir a verificação pela equipe.

Por que não dá para excluir uma vaga que já tem candidaturas?

Para não apagar o histórico das candidatas; a vaga é encerrada.

Capítulo 9

Rede social e comunidades

Feed

Publicações com tipo (dica, experiência, projeto, conquista, oportunidade, dúvida), imagem opcional (reduzida no navegador antes do envio), curtidas, comentários, edição e denúncia. Abas "Para você" e "Quem eu sigo".

  • Coluna lateral (telas largas): meu perfil com números, "Complete seu perfil", assuntos em alta, comunidades para participar e quem seguir.
  • Hashtags: #assunto vira link para a busca. "Assuntos em alta" conta as hashtags dos últimos 14 dias (GET /api/comunidade/em-alta).
  • Publicações novas: a cada minuto o feed confere se alguém publicou e mostra o botão "N publicações novas".

Comunidades

Abas Descobrir e Minhas comunidades, cartões com capa, fotos de quem participa e atividade da semana. Cada comunidade tem abas Publicações, Participantes e Sobre (descrição e regras). Quem criou troca a capa e o ícone, edita as regras, tira publicações da comunidade e recebe um aviso quando alguém entra.

Revisão

O que acontece com uma publicação que a criadora tira da comunidade?

Ela some da comunidade, mas continua no feed e no perfil de quem publicou.

Um # dentro de um link (como site.com/a#ancora) conta como assunto?

Não: a regra só aceita a hashtag no começo do texto ou depois de espaço/pontuação.

Capítulo 10

Mensagens e notificações

Mensagens em duas colunas, como num app de conversa: lista à esquerda (busca, abas Candidatas/Empresas, prévia, hora, "✓✓" e não lidas) e a conversa à direita. No celular, uma coluna por vez.

RecursoComo funciona
Conversas com empresasSempre ligadas a uma candidatura: só conversa quem tem um processo seletivo em comum.
Conversas entre candidatasAbertas pelo perfil de outra integrante ou por "Nova conversa".
ImagensJPG, PNG ou WebP até 2 MB, reduzidas no navegador antes do envio.
Visto e ✓✓A API devolve até qual mensagem a outra pessoa já leu (lidasAte).
ApagarQuem enviou apaga a própria mensagem; o texto e a imagem saem do banco.
Ao vivoA conversa aberta busca só as mensagens novas a cada 5 segundos (?depois=).
Bloquear e denunciarNo menu "⋯" da conversa entre candidatas. Bloqueada, a pessoa não envia mensagens nem abre conversa nova.
Não lidas no topoO ícone de mensagens mostra o total (GET /api/mensagens/nao-lidas).

Notificações

O sino mostra as não lidas. Cada categoria pode ser desligada em Configurações (candidata: vagas compatíveis, candidaturas, mensagens, convites, comunidade, plataforma; empresa: candidaturas, mensagens, plataforma).

Revisão

Quem bloqueou consegue mandar mensagem para quem foi bloqueada?

Não: enquanto houver bloqueio em qualquer sentido, ninguém envia. Quem bloqueou pode desbloquear.

Por que a conversa com empresa precisa de uma candidatura?

Para evitar mensagens não solicitadas: só conversa quem tem um processo seletivo em comum.

Capítulo 11

Bloom Premium

Assinatura mensal de R$ 99,90 para candidatas e para empresas, paga pelo Mercado Pago; empresas também podem comprar campanhas de divulgação (R$ 150,00).

  • Assinar
  • →
  • Página do Mercado Pago
  • →
  • Webhook avisa a API
  • →
  • API confere no Mercado Pago

Nada vira "ativo" ou "pago" sem a API reler o pagamento no Mercado Pago. O que o Premium muda: vagas de empresas Premium aparecem primeiro com selo "Destaque", candidatas Premium aparecem primeiro no banco de talentos e o perfil ganha o selo Premium.

Revisão

Por que a API não confia só no aviso do webhook?

Porque qualquer um poderia mandar um aviso falso; a API confere a assinatura do aviso e sempre relê o status direto no Mercado Pago.

Capítulo 12

Administração

NívelPode
superTudo: moderação, excluir contas, administradores, comunicados e relatórios
moderadorPainel, contas (ver, suspender, reativar, confirmar representante), moderação de conteúdo, denúncias, pagamentos (leitura) e registro
  • Segurança da equipe: login próprio com limite de tentativas, verificação em duas etapas (app autenticador + 8 códigos de recuperação) e troca obrigatória da senha inicial.
  • Moderação: suspender (bloqueia o login e esconde o conteúdo), reativar, excluir, remover publicações, comentários, comunidades e encerrar vagas — sempre com motivo.
  • Denúncias: fila com o conteúdo denunciado e ações diretas; quem foi denunciado não sabe quem denunciou.
  • Comunicados para todas as contas, só candidatas ou só empresas.
  • Relatórios CSV com CPF mascarado e proteção contra fórmulas no Excel.
  • Registro de ações: tudo o que a equipe fez, com quem, quando e por quê.

Revisão

O que acontece com o conteúdo de uma conta suspensa?

Some para as outras pessoas (publicações, comentários, perfil e listas) e volta ao reativar.

Para que servem os códigos de recuperação das duas etapas?

Para entrar sem o celular; cada código vale um login.

Capítulo 15

Segurança e privacidade

Proteções da conta

  • Senhas com bcrypt; tokens JWT assinados e com validade.
  • Limites de tentativas por IP e por conta (login, cadastro, senha, confirmação de e-mail, envio de links).
  • Links de e-mail com token aleatório de uso único; só o hash fica no banco.
  • Administradores com duas etapas e conferência da conta no banco a cada pedido.

Permissões no servidor

Toda regra de "quem pode" é conferida na API, nunca só na tela: a empresa só vê as próprias candidaturas, só quem enviou apaga a mensagem, só quem criou edita a comunidade.

Arquivos e imagens

O tipo do arquivo é conferido pelos primeiros bytes, não pelo nome. Imagens são servidas por uma chave aleatória de 128 bits, impossível de adivinhar.

Privacidade da candidata (LGPD)

  • Perfil oculto some de buscas, listas e comunidades.
  • O CPF nunca aparece inteiro fora do cadastro (nos relatórios, mascarado).
  • Excluir a conta apaga os dados dela de verdade.
  • Bloqueio e denúncia no chat, e quem foi denunciado não sabe quem denunciou.

Revisão

Por que conferir o tipo do arquivo pelos primeiros bytes?

Porque o nome pode mentir: alguém poderia renomear um programa para ".pdf". Os primeiros bytes mostram o formato real.

O que é "injeção de fórmula" nos relatórios CSV?

Um texto que começa com =, +, - ou @ pode virar fórmula no Excel; a exportação neutraliza essas células.

Por que os testes usam e-mails terminados em .test?

Porque .test é um domínio reservado: nenhum e-mail real é enviado e dá para apagar as contas de teste com segurança.

Capítulo 17

Glossário

APIA parte do sistema que recebe pedidos (/api/...) e responde com dados.
JWTToken assinado que prova quem está logada, enviado em cada pedido.
HashTransformação de mão única: dá para conferir uma senha, não para recuperá-la.
MigrationArquivo SQL que muda a estrutura do banco, aplicado uma vez.
MiddlewareFunção que roda antes do controller, como a conferência de login.
WebhookAviso que um serviço externo (Mercado Pago) envia para a API.
TOTPCódigo de 6 dígitos que muda a cada 30 segundos, usado nas duas etapas.
LGPDLei Geral de Proteção de Dados: direito de ver, corrigir e apagar os próprios dados.
RascunhoVaga salva que ainda não está publicada.
SuspensãoBloqueio da conta pela equipe; o conteúdo fica oculto até reativar.
